# שלב ה' - דוח פרויקט: ממשק משתמש גרפי (GUI) למערכת RideFlow

ממשק גרפי זה נבנה כרשת ניהול נסיעות מתקדמת ודינמית המאפשרת שליטה מלאה על מסד הנתונים `merged` (בסיס נתונים מסוג PostgreSQL). המערכת תוכננה מן היסוד על מנת לספק חוויית משתמש חלקה, מהירה ומודרנית תוך התמודדות יעילה עם עשרות אלפי רשומות הקיימות במסד הנתונים.

הממשק מעוצב בקו נקי ותומך במצב כהה (Dark Slate Theme) מלא עם התאמה מושלמת לעברית (RTL).

## 🚀 הוראות הפעלה והרצה

### דרישות קדם:
1. **מכולת Docker**: ודא כי בסיס הנתונים PostgreSQL רץ במכולת ה-Docker שלו (מנוהל דרך `docker-compose` בתיקיית השורש של הפרויקט).
2. **סביבת פייתון (Python)**: ודא כי מותקנות אצלך ספריות הפייתון הדרושות להרצת השרת:
   ```bash
   pip install flask psycopg2-binary python-dotenv
   ```
3. **קובץ הגדרות סביבה (`.env`)**: המערכת משתמשת בקובץ הגדרות בשורש הפרויקט לחיבור מאובטח ל-PostgreSQL.

### פקודת ההרצה:
1. פתח את הטרמינל או ה-PowerShell בתיקיית הפרויקט.
2. נווט לתיקיית שלב ה' והרם את השרת:
   ```bash
   cd ex5
   python app.py
   ```
3. לאחר קבלת הודעה שהשרת רץ בהצלחה, פתח את הדפדפן והיכנס לכתובת:
   [http://127.0.0.1:5000](http://127.0.0.1:5000)

## 🛠️ הסבר על ארכיטקטורה, דרך העבודה והכלים

המערכת נבנתה בארכיטקטורת **Client-Server** מודרנית תוך הפרדה מוחלטת בין שכבת התצוגה (Frontend) לשכבת הלוגיקה והנתונים (Backend). התקשורת בין שתי השכבות מבוססת על פרוטוקול HTTP אסינכרוני באמצעות **RESTful API** המעביר נתונים בפורמט JSON.

---

### 1. שרת ה-Backend (פייתון ומסד הנתונים)
שרת ה-Backend מבוסס על שפת **Python 3** וממוקם בקובץ המרכזי [app.py](file:///c:/Users/Home/rideFlowProject/ex5/app.py). השרת מנהל את כל הקשר למסד הנתונים `merged` (PostgreSQL) ומספק נקודות קצה (API Endpoints) מאובטחות ויעילות:

* **שרת Flask**:
  * משמש כליבת שרת האינטרנט ומנגיש את קובצי התצוגה הסטטיים של הממשק.
  * מספק API קל ומהיר לקריאה אסינכרונית. השימוש ב-Flask מאפשר שליפה ממוקדת של מידע בפורמט JSON ללא צורך ברינדור של הדף מחדש בצד השרת (Server-side rendering), דבר המאיץ דרמטית את זמן התגובה של האתר.
  
* **קישוריות מנוהלת באמצעות Psycopg2**:
  * שימוש ב-`psycopg2` מאפשר התחברות יציבה לשרת ה-PostgreSQL המקומי (פורט 5432).
  * עבודה עם **`RealDictCursor`**: כלי זה הופך כל שורה שנשלפת מבסיס הנתונים למילון פייתון דינמי (`dict`) שבו המפתח הוא שם העמודה ב-SQL. הדבר מאפשר המרה ישירה ויעילה ל-JSON (על ידי `jsonify`) ללא צורך בלולאות המרה ידניות יקרות בזיכרון.
  
* **אבטחה והגדרות סביבה (`python-dotenv`)**:
  * פרטי החיבור למסד הנתונים (שם משתמש, סיסמה, שם בסיס הנתונים ופורט) אינם קשיחים בקוד. הם נטענים בצורה מאובטחת מקובץ הגדרות הסביבה [.env](file:///c:/Users/Home/rideFlowProject/.env) באמצעות ספריית `dotenv`, כמקובל בסטנדרטים של פיתוח תוכנה מודרני (12-Factor App).
  
* **ניהול עסקאות (Transactions) ובטיחות נתונים**:
  * במצב כתיבה/עדכון, השרת מוגדר לנהל עסקאות בצורה אטומיקלית (Atomic).
  * בקשות מריצות את השאילתות, ואם מתרחשת שגיאה כלשהי (כולל חריגות שנזרקות מהטריגרים ב-PostgreSQL), מתבצע אוטומטית `rollback` המבטל את כל השינויים שבוצעו באותה בקשה, כדי למנוע מצב של חצי-רישום או חוסר עקביות בנתונים.
  
* **ניטור הודעות ומערכת לוגים מובנית (DB Notice Logs)**:
  * השרת עושה שימוש במערך ההודעות של PostgreSQL (`conn.notices`). כאשר פרוצדורת ביטול נסיעה או הרשמה מריצה פקודת `RAISE NOTICE`, פייתון מאזין להודעות אלו, אוסף אותן ומחזיר אותן לקליינט. זה מאפשר למשתמש לראות ממש על המסך את "לוג הריצה" של בסיס הנתונים בזמן אמת.

### 2. ממשק המשתמש (Frontend - SPA)
ממשק המשתמש נבנה כיישום בעל דף בודד (**Single Page Application**) הממוקם תחת התיקייה [static](file:///c:/Users/Home/rideFlowProject/ex5/static):

* **HTML5 סמנטי ומבנה נגיש** ([index.html](file:///c:/Users/Home/rideFlowProject/ex5/static/index.html)):
  * שימוש בתגיות HTML5 סמנטיות מובנות (`<aside>`, `<main>`, `<section>`, `<header>`) המבטיחות חלוקה נכונה של הדף, קריאות גבוהה למנועי חיפוש ונגישות לטכנולוגיות מסייעות.
  * כתיבה מותאמת לעברית מלכתחילה (`dir="rtl"`) למניעת באגים ויזואליים בתצוגת הטקסט.
  
* **עיצוב מודרני מונחה ביצועים (CSS3 Custom Styling)** ([style.css](file:///c:/Users/Home/rideFlowProject/ex5/static/css/style.css)):
  * **Slate Dark Theme**: עיצוב מבוסס פלטת צבעים כהה, אלגנטית ומודרנית שמותאמת לעבודה ממושכת ללא עייפות עיניים.
  * **Glassmorphism**: יצירת אפקטים של זכוכית שקופה למחצה על ידי שילוב של `backdrop-filter` וטשטוש (Blur), המשפרים את המראה האסתטי הכללי של כרטיסי המידע וחלונות הדיאלוג.
  * **משתני CSS (CSS Variables)**: שימוש ב-Custom Properties לניהול מרוכז של מערכת הצבעים, הריווחים והגופנים באתר, המקל על תחזוקת העיצוב.
  * **אנימציות מיקרו (Micro-animations)**: אפקטי מעבר עדינים (`transition`) ושינוי גודל קל בזמן ריחוף (Hover) מעל כפתורים, תפריטים ושדות קלט, המעניקים תחושה דינמית וחלקה של ממשק חי.
  
* **לוגיקה אסינכרונית בצד הלקוח (Vanilla JavaScript - ES6)** ([main.js](file:///c:/Users/Home/rideFlowProject/ex5/static/js/main.js)):
  * **ניהול מצב (State Management) אסינכרוני**: ניהול נתוני הטבלה בזיכרון המקומי ומעבר מהיר בין כרטיסיות (Tabs) ללא רענון הדף כלל.
  * **בנייה יעילה של ה-DOM (Array Join Performance)**: יצירת טבלאות וטפסים מרובי שורות מתבצעת על ידי הרכבת מערך מחרוזות וביצוע `join` יחיד לתוך ה-`innerHTML`. שיטה זו מהירה פי עשרות מונים מביצוע מניפולציות DOM נפרדות לכל שורה, ומונעת תופעות של Reflow ו-Repaint של הדפדפן.
  * **שילוב והרצת שאילתות מורכבות ופונקציות**: הממשק שולח בקשות `POST`/`GET` מותאמות ומציג את תוצאות השאילתות ישירות בטבלאות דינמיות.

### ⚡ אופטימיזציות מיוחדות לעבודה עם עשרות אלפי נתונים
כדי למנוע קריסה או קפיאה של הדפדפן עקב כמות הנתונים העצומה במסד הנתונים, הוטמעו הפתרונות הבאים:
1. **טעינה עצלה של אפשרויות (Lazy Options Loading)**: טעינת אפשרויות הבחירה (Dropdowns) של הנהגים, הנוסעים והנסיעות מתבצעת פעם אחת בלבד ורק בעת כניסה למסך הרלוונטי או פתיחת חלון הוספה/עריכה, במקום לטעון את כל הנתונים מראש (דבר המונע עומס וקפיאה של הדפדפן).
2. **הגבלת תוצאות ודפדוף (Query Limits)**: בשרת [app.py](file:///c:/Users/Home/rideFlowProject/ex5/app.py) הוגדר LIMIT דינמי לשאילתות (ברירת מחדל של 100 רשומות, מקסימום 500) המונע שליפה של עשרות אלפי שורות בבת אחת לדפדפן.
3. **סינון בצד הלקוח מבוסס Cache (Fast Client-Side Filtering)**: מנגנון החיפוש הדינמי בטבלאות אינו פונה לשרת בכל הקלדה ואינו סורק את ה-DOM (דבר שיוצר האטה משמעותית). במקום זאת, הוא יוצר Cache טקסטואלי מראש ומסנן שורות בזיכרון באופן מיידי.
4. **פתרון מפתחות זרים ידידותי**: המערכת מבצעת שאילתות `JOIN` מובנות בשרת כדי להציג שמות ברורים (כמו שם הנהג, שם הנוסע, מזהה נסיעה מפורט ושמות תחנות מילוליים) במקום להציג מזהים מספריים חסרי משמעות.

### 7. פונקציות ופרוצדורות (שלב ד')
במסך זה המשתמש יכול להפעיל את תתי-התוכניות שנכתבו ב-PL/pgSQL בשלב ד' של הפרויקט:

#### א. הרצת פרוצדורות (Procedures)
- **ביטול נסיעה ועדכון הרשמות (`cancel_trip_and_notify`)**: מבצע ביטול נסיעה ומעדכן את כל הנוסעים הרשומים אליה לסטטוס 'Cancelled' באמצעות Cursor. בתמונה ניתן לראות את הודעות ה-`NOTICE` המפורטות המוחזרות ישירות ממסד הנתונים.
- **הרשמת נוסע לנסיעה עם עדכון מקומות (`register_passenger_to_trip`)**: רושם נוסע לנסיעה ומפחית אוטומטית את כמות המושבים הפנויים בנסיעה ב-1.
![הרצת פרוצדורות](screenshots/Screenshot%202026-06-21%20200032.png)

#### ב. הרצת פונקציות (Functions)
- **שליפת נסיעות פעילות של נוסע (`get_passenger_active_trips`)**: מחזירה Ref Cursor המכיל את כל הנסיעות והסטטוסים של הנוסע, והממשק הגרפי מציג אותן בטבלה.
- **חישוב מקומות פנויים במסלול (`get_route_available_seats`)**: מחשבת באמצעות Explicit Cursor סורק ולולאה את כמות המושבים הפנויים הכוללת במסלול מסוים ומציגה את המספר למשתמש.
![הרצת פונקציות](screenshots/Screenshot%202026-06-21%20195746.png)
